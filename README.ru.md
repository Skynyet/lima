# SkyNyet Lima: сеть с общей памятью для VZ-машин

[English version](README.md)

Это proof-of-concept (PoC): пара форков [Lima v2.2.0](https://github.com/lima-vm/lima/blob/v2.2.0/README.md) и [socket_vmnet v1.2.2](https://github.com/lima-vm/socket_vmnet/blob/v1.2.2/README.md). Они не являются официальными релизами.

## Зачем

Основная мотивация — ускорить shared-сеть ванильной пары. При обмене двух VM ретрансляция каждого Ethernet-кадра через stream-сокет добавляет переключения между процессами, копирование и системные вызовы к трафику, которому вообще не нужен vmnet.

Начальная версия использовала отдельный координатор шины с общей памятью; теперь он встроен *непосредственно* в `socket_vmnet`. Lima автоматически подключает hostagent каждой VZ-машины к шине через дополнительный Unix-сокет управления. Кадры между VM идут напрямую через общие кольцевые буферы, а демон выступает как vmnet-uplink для связи с хостом и внешней сетью. У сети Lima `shared` сокет шины называется `socket_vmnet_shm.shared` и находится рядом с исходным `socket_vmnet.shared`.

## Возможности и исправления

- **Автоматическое подключение и fallback.** Для VZ-машин Lima находит сокет шины без специального флага. Если его нет, Lima предупреждает и использует прежний framed-путь; если сокет есть, но подключение не работает, выдаёт ошибку.
- **Одна зависшая VM не блокирует обмен остальных.** Hostagent каждой VM читает своё кольцо независимо. Если получатель удерживает занятый слот, кадр может быть сброшен, но остальные участники не ждут его сокет.
- **Восстановление без перезапуска VM.** После перезапуска координатора hostagent подключается к шине заново. Зависшее подключение можно прервать при остановке VM.
- **Независимые MTU.** Lima задаёт MTU сегмента `socket_vmnet` и MTU сетевого VZ-attachment отдельно. MTU VM можно указать числом или сослаться на MTU сети; он намеренно может отличаться от MTU шины, например для тестирования PMTU discovery.
- **Пакетная обработка на границе VZ.** Darwin `recvmsg_x`/`sendmsg_x` обрабатывают кадры пачками в обоих направлениях; если эти вызовы недоступны, используются обычные datagram-операции.

## Быстродействие

- При MTU 1500 ванильная Lima с upstream `socket_vmnet` дала 2,38 Gbps между двумя VM; шина с общей памятью — 9,88 Gbps (23,4 Gbps при MTU 9000).
- С подключённым vmnet-uplink пара VM держала около 5,67 Gbps **в каждом направлении (bidir)** при MTU 1500 и четырёх TCP-потоках на направление.
- Остановка и повторное подключение третьей, простаивающей VM не прервали обмен host↔VM: 7,91, 7,84 и 7,72 Gbps. После отключения vmnet-uplink две VM продолжили обмен.
- Пакетная обработка на границе VZ снизила расход CPU hostagent на 30,2% в расчёте на GB.

Быстрый путь шины работает для VZ-машин в сетях `socket_vmnet`. QEMU, `user-v2` и VZ NAT его не используют.
